# IterPert 近期实验结果

数据：Replogle K562 Essential 1K。主动学习预算：初始 \(n=100\)，每轮查询 \(100\)，共 \(5\) 轮至 \(n=600\)。  
主指标 \(P(n)\) 为 hold-out 扰动效应的 Pearson \(\delta\)。曲线面积

\[
\mathrm{nALC}
=
\frac{1}{n_{\max}-n_{\min}}
\int_{n_{\min}}^{n_{\max}} P(n)\,dn
\]

用梯形法则计算。论文 IterPert 为 **8 个 prior kernel + 模型 kernel 等权融合**（`mean_new` / `max`）。

Kernel alignment（与代码一致，未中心化）

\[
\mathrm{KA}(A,B)
=
\frac{\mathrm{tr}(AB)}{\|A\|_F\|B\|_F}.
\]

## 2. 干净设定：动态融合权重

记模型权重 \(w\in\{0,0.25,0.5,0.75,1\}\)，剩余质量均分给 8 个 prior。论文等权相当于 \(w\approx 1/9\)。

### 2.1 手写 schedule（5 seed）

| 策略 | 平均 nALC | \(P(600)\) |
|------|:---------:|:----------:|
| 论文等权 | **0.252** | 0.288 |
| Early-Model（先信模型） | 0.250 | 0.281 |
| 固定 \(w=0.75\) | 0.249 | 0.280 |
| 固定 \(w=0.5\) | 0.248 | 0.289 |
| Early-Prior（先信 prior） | 0.245 | 0.274 |

等权最好，Early-Prior 最差。

### 2.2 Common-state fork（3 run \(\times\) \(\{100,300,500\}\) \(\times\) 5 个 \(w\)）

在同一已标注集 \(S\)、同一 checkpoint 上只改 \(w\)，看下一 query 的增益 \(\Delta P(w\mid S)\)。对比

\[
C(S)
=
\overline{\Delta P}\bigl(w\in\{0.75,1\}\bigr)
-
\overline{\Delta P}\bigl(w\in\{0,0.25\}\bigr).
\]

\(C<0\)：偏 prior 更好；\(C>0\)：偏模型更好。

| \(n=\lvert S\rvert\) | run1 | run2 | run3 | \(C>0\) |
|:---:|:---:|:---:|:---:|:---:|
| 100 | \(-0.0015\) | \(-0.0058\) | \(-0.037\) | 0/3 |
| 300 | \(-0.0097\) | \(-0.012\) | \(-0.021\) | 0/3 |
| 500 | \(-0.017\) | \(-0.0054\) | \(-0.0041\) | **0/3** |

全部 9 个 \(C(S)<0\)。早期确实偏 prior，但后期**没有**翻转到偏模型。\(w=0\) 与 \(w=1\) 选出的基因 Jaccard \(\approx 0.03\)：权重改了动作，却没有可复现的阶段依赖偏好。

Labeled-set 上 prior–观测 KA 一直较高，与 nALC 的 Spearman 接近 0 或不显著，不能当 \(w_t\) 的可靠性信号。

**结论：** 干净数据上，round / \(\lvert S\rvert\) 不是设 \(w_t\) 的正确轴；等权融合很难被手写 schedule 超过。

## 3. 不可靠 prior：损伤、检测、干预

对象：较强、可解释的 RPE1 Perturb-seq prior。用固定基因置换 \(P\) 破坏**基因对应关系**（不破坏谱）：

\[
K_\lambda
=
(1-\lambda)\,K_{\mathrm{RPE1}}
+
\lambda\, P K_{\mathrm{RPE1}} P^\top,
\qquad
\lambda\in\{0,\,0.5,\,1\}.
\]

\(\lambda=1\) 为完全语义错配。Campaign seed \(1\)–\(3\)；主置换 seed `20260826`。

### 3.1 损伤（同 seed 配对）

\[
D(\lambda,r)
=
\mathrm{nALC}(\text{clean},r)
-
\mathrm{nALC}(\lambda,r),
\qquad
H(1,r)
=
\mathrm{nALC}(\text{oracle-drop},r)
-
\mathrm{nALC}(\text{full }\lambda=1,r).
\]

\(D>0\)：corruption 伤了该 seed。Oracle-drop = 删掉 RPE1，其余 prior + 模型仍等权。\(H\) 相对的是**带坏 prior 的 full**，不是干净 IterPert。

| run | \(D_{\mathrm{two}}(0.5)\) | \(D_{\mathrm{two}}(1)\) | \(D_{\mathrm{full}}(0.5)\) | \(D_{\mathrm{full}}(1)\) | \(H(1)\) |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 1 | \(+0.0073\) | \(+0.023\) | \(+0.0008\) | \(+0.018\) | \(+0.0030\) |
| 2 | \(+0.0071\) | \(+0.029\) | \(+0.0009\) | \(+0.030\) | \(+0.019\) |
| 3 | \(+0.0051\) | \(+0.028\) | \(+0.0091\) | \(+0.017\) | \(-0.0027\) |
| 符号 | 3/3 | **3/3** | 3/3 | **3/3** | 2/3 |

- Two-source（仅 model + RPE1）与 full（8 prior + model）在 \(\lambda=1\) 上都 **3/3** 下降；多 prior 平均**吸收不掉**一个坏 RPE1。
- \(\lambda=0.5\) 的 \(D_{\mathrm{full}}\) 很小（约 \(10^{-3}\)），中等错配几乎不伤 nALC。
- Oracle 删除在 2/3 seed 能挽回一部分损失，run3 略反向；恢复比例 \(H/D_{\mathrm{full}}\) 均值约 \(0.21\)，异质很大。

**结论：** 完全语义错配会稳定伤 campaign；删掉坏 prior 有一定 headroom，但不是每个 seed 都划算。3 seed 只说明现象可重复，不够支撑方法 claim。

### 3.2 检测（同一 \(S_t\)，只改 RPE1 的 \(\lambda\)）

15 个共同状态（3 run \(\times\) \(\lvert S\rvert\in\{100,200,300,400,500\}\)），5 个置换 seed。合法信息：当前已选基因、其观测表达 \(K_y[S,S]\)、当前模型 Gram、prior kernel。不用未标注基因的表达，也不用 \(\lambda\) 标签。

\[
z_{\mathrm{obs}}(S,\lambda)
=
\mathrm{KA}\bigl(K_\lambda[S,S],\,K_y[S,S]\bigr).
\]

另两个过门信号：prior–model KA、局部 10-NN 与观测邻域重叠。Cross-prior consensus 只对 \(\lambda=1\) 有分离。

主置换 seed 上 Observed KA 的 median \(z\)：

\[
z_{\mathrm{obs}}:\quad
\lambda=0:\ 0.55,\quad
\lambda=0.5:\ 0.48,\quad
\lambda=1:\ 0.22.
\]

| 信号 | \(\Delta z_{0,1}>0\) | \(\Delta z_{0,0.5}>0\) |
|------|:---:|:---:|
| Observed KA | 15/15（5 个 perm 全过） | 15/15 |
| Prior–model KA | 12/12（\(n=500\) 无模型 Gram） | 12/12 |
| Local 10-NN | 15/15 | 15/15 |
| Cross-prior consensus | 12/15 | **0/15** |

\(\lambda=1\) 与 clean 几乎无重叠；\(\lambda=0.5\) 也能被 Observed KA 分开，但 §3.1 显示此时 nALC 几乎不动。因此 **KA 下降 \(\neq\) 应该拒绝**。

**结论：** 用已观测反馈可以识别 RPE1 是否严重不可靠；consensus 只能抓完全错配。这是机制结果，还不是部署规则。

### 3.3 硬剔除（held-out 置换 `20260831`）

检测器只用 Observed KA。阈值只在 calibration perm \(\{20260826,27,28\}\) 上按 \(\mathrm{FPR}_{\mathrm{clean}}\le 10\%\) 选定，validation / holdout / GPU test 不回看 nALC：

\[
\tau^\star = 0.451,\qquad
\mathrm{FPR}=0,\ \mathrm{TPR}=1
\quad\text{（cal / val / holdout 均如此）}.
\]

规则：从第一轮 query 起，若 \(z_{\mathrm{RPE1}}<\tau\) 则本轮丢掉 RPE1，其余 kernel 仍等权。

\[
R_{\mathrm{recover}}(r)
=
\mathrm{nALC}_{\mathrm{detected}}(r)
-
\mathrm{nALC}_{\mathrm{equal\ corrupt}}(r),
\]

\[
C_{\mathrm{clean}}(r)
=
\mathrm{nALC}_{\mathrm{equal\ clean}}(r)
-
\mathrm{nALC}_{\mathrm{detected\ clean}}(r).
\]

\(R>0\)：corrupt 上挽回了；\(C>0\)：clean 上比等权更差。

| run | \(R_{\mathrm{recover}}\) | \(C_{\mathrm{clean}}\) | 等权 clean | detected clean | 等权 \(\lambda=1\) | detected \(\lambda=1\) | oracle |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 1 | \(+0.0017\) | \(+0.0046\) | 0.249 | 0.244 | 0.242 | 0.243 | 0.234 |
| 2 | \(-0.0042\) | \(+0.0001\) | 0.256 | 0.256 | 0.244 | 0.239 | 0.245 |
| 3 | \(-0.0071\) | \(+0.024\) | 0.250 | 0.225 | 0.231 | 0.224 | 0.231 |
| 计数 | \(R>0\)：**1/3** | \(C>0\)：**3/3**（均值 \(+0.010\)） | | | | | |

Corrupt 上平均没有挽回（mean \(R=-0.003\)）；clean 上 3/3 变差，run3 掉了 \(0.024\) nALC。Oracle 本身在 run1/3 就低于「带着坏 prior 等权」，硬删并不总是对的。

**结论：** 检测器在离线状态上很干净，但二元丢掉既救不回 corrupt campaign，还会伤 clean fusion。

---

## 4. 三句话

1. **干净设定**：等权融合很难被 round-wise 重加权打败；权重会改选哪些基因，但没有随 \(\lvert S\rvert\) 翻转的偏好。
2. **坏 prior**：RPE1 完全语义错配会稳定降低 two-source 和 full IterPert；多源平均吸收不掉。
3. **检测 vs 干预**：用已观测 KA 可以分开 clean / 错配，但按阈值硬剔除不能恢复 nALC，且在干净 prior 上有代价。

以上均基于 3 个 campaign seed（schedule 实验为 5 seed）。损伤方向稳定，幅度和 oracle 恢复仍异质，尚不足以写成方法。
